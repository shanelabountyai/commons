# Security audit: event-toolkit

- **Repo:** `/Users/shanelabounty/Projects/event toolkit/event-planner-app` (git root is `/Users/shanelabounty/Projects/event toolkit`, remote `shanelabountyai/event-toolkit`)
- **Live:** eventoolkit.labintelligence.co / event-toolkit.vercel.app (Vercel project `event-toolkit`)
- **Stack:** Next 15.5.23, next-auth 5.0.0-beta.32 (Resend magic link, DrizzleAdapter, database sessions), Drizzle 0.44 + postgres.js on Neon, pnpm monorepo. There is no `middleware.ts`.
- **Exposure summary:** An optional hosted tier holds attendee PII (leads, survey responses). Authorization is centralised and scoped well. The main hole is that an **admin can make themselves owner and take over a workspace**. Beyond that, bearer tokens are stored raw, and there is no rate limiting and no security headers.

Method: read-only review of every tracked route handler (6), every `'use server'` file (8), the workspace pages, `packages/server-db`, `packages/access`, config and CI. Nothing was run. Auth.js library behaviour was checked in `node_modules/@auth/core@0.41.3`.

## Gaps

| ID | Sev | Finding | Fix | Acceptance test |
|---|---|---|---|---|
| SEC-01 | **HIGH** | **Admin can grant owner, including to themselves, and then remove the real owner.** `changeRole` checks only whether the *target's current* role is owner (`packages/server-db/src/workspaces.ts:152`), never the *new* role. `inviteMember` accepts any role (`workspaces.ts:217-231`), and the action only checks that the role is in `ROLES` (`members/actions.ts:52,67`). **Exploit:** an admin posts `changeRoleAction` with `userId=<self>&role=owner`, then `removeMemberAction` against the original owner. That is a full workspace takeover, including `workspace:delete`, and the owner's sessions are deleted (`workspaces.ts:208`). | In `changeRole` and `inviteMember`, refuse `newRole === "owner"` (and any change to an owner) unless `ctx.role === "owner"`. Put the rule in `packages/access` as `canGrantRole(actor, role)`. | `access-check`/`server-db-check`: with an admin ctx, `changeRole(db, ctx, ctx.userId, "owner")` and `inviteMember(db, ctx, x, "owner")` both throw `not_permitted`. The owner-ctx equivalents succeed. |
| SEC-02 | MED | **Bearer tokens stored raw.** `invitations.token` (`schema.ts:154`), `share_links.token` (`schema.ts:185`) and `sessions.sessionToken` (`schema.ts:92`) are looked up by equality (`workspaces.ts:281,318`, `share-links.ts:93`). **Exploit:** anyone with DB read access gets working credentials: a Neon console user, a backup, the leaked `.env.local` connection string, or a `SELECT` in a log. They can read live run-of-show links, accept pending invites if they control the email, and replay sessions. | Store `sha256(token)` and look up by hash. Show share tokens once at creation instead of listing them (`share/page.tsx:85`). For sessions, override the adapter's `createSession`/`getSessionAndUser` to hash, or accept this as an Auth.js limit and document it. | A unit test inserts a link, asserts the column value is not equal to the returned token, and asserts `resolveShareLink(rawToken)` still resolves. |
| SEC-03 | MED | **No rate limit on `requestSignInLink`** (`sign-in/actions.ts:19-40`). **Exploit:** a script calls the server action in a loop with a victim's address. That mail-bombs the victim, burns the Resend quota and hurts sender reputation, and it is unauthenticated. | A per-IP and per-email limit in Postgres (a table with a windowed count) or Upstash, checked before `signIn`. | The 6th request for the same email within 15 min returns the generic success without sending, verified by a mocked provider call count. |
| SEC-04 | MED | **No security headers.** Only `X-Robots-Tag` is set (`next.config.ts:34-36`). No `frame-ancestors`/XFO, nosniff or Referrer-Policy. HSTS on the custom domain is UNVERIFIED (Vercel may add it). **Exploit:** members and privacy pages can be framed for clickjacking, and share-link URLs (the path holds the token) leak in `Referer` to any outbound link. | Add a global `headers()` entry: `X-Frame-Options: DENY` / `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` (`no-referrer` plus `Cache-Control: no-store` on `/share/*` and `/invite/*`), and HSTS. | `curl -sI https://eventoolkit.labintelligence.co/share/x` shows all four headers plus `no-referrer` and `no-store`. |
| SEC-05 | LOW | **Magic link is consumed by GET** (Auth.js `/api/auth/callback/resend?token=`). **Exploit:** a corporate mail scanner (Safe Links, Mimecast) that follows links spends the one-time token. Users see "link invalid", and the scanner gets a session cookie that it discards. | An interstitial "Sign in" button page that POSTs to the callback, via a custom `sendVerificationRequest` URL pointing at an app page. | Fetching the emailed URL with GET does not create a `sessions` row. The POST from the button does. |
| SEC-06 | LOW | **Unauthenticated, unlimited writes via share link.** `logIssueAction` (`share/[token]/actions.ts:19-64`) inserts a new `records` row per call with a random id (`:52`). **Exploit:** anyone holding a forwarded link can insert unlimited 500-char issues into the workspace's synced data, and every member device then pulls them. | A per-token limit (e.g. 30/hour) in the DB, plus a per-pack cap on open issues. | The 31st issue in an hour via one token returns an error and no row is written. |
| SEC-07 | LOW | **Cron secret uses `!==`** (`api/cron/retention/route.ts:23`). This is a timing side channel. The practical risk is low, but it fails the K8 rule. | `crypto.timingSafeEqual` on equal-length buffers. | A unit test: a wrong secret of the same length gives 401 and the right one gives 200. The code uses `timingSafeEqual`. |
| SEC-08 | LOW | **PII can reach logs.** Raw `console.error(error)` bypasses `lib/redact.ts` in `members/actions.ts:40`, `privacy/actions.ts:48,61,80`, `share/actions.ts:39,52`, `invite/[token]/actions.ts:27` and `sign-in/actions.ts:35`. Drizzle 0.44 query errors include bound params (UNVERIFIED for this exact version), so a failed subject search can log the data subject's email. Separately, `/verify?email=` (`sign-in/actions.ts:39`) puts the address in request logs. | Route all of these through `log.error`, and drop the email from the redirect (use a flash cookie or just "check your inbox"). | Grep shows no `console.` calls in `apps/web/app/**/actions.ts`. The `/verify` URL carries no query. |
| SEC-09 | LOW | **Attendee-data reads via sync pull are not access-logged.** `pullRecords` (`records.ts:292-330`) returns `leadRecords`/`surveyResponses` without an `access_events` row, although `privacy.ts:296` exports `LOGGED_KINDS` "so the pull path can apply the same rule". **Exploit:** a planner can bulk-exfiltrate every lead through `/api/sync/pull` and leave no audit entry (PRD 10 FR-6 gap). | In `pullRecords`, when any visible row's kind is in `LOGGED_KINDS`, insert one `access_events` row with counts. | A pull by a planner in a workspace with a lead record adds one `privacy.pii_pulled` event. A pull by finance adds none. |
| SEC-10 | LOW | **The audit log is mutable.** `access_events` has no DB-level append-only enforcement, and it is `ON DELETE CASCADE` from `workspaces` (`schema.ts:204-206`). | Add a migration: `REVOKE UPDATE, DELETE` from the app role, or a `BEFORE UPDATE OR DELETE` trigger that raises. Reconsider the cascade. | `UPDATE access_events ...` as the app role errors. |
| SEC-11 | LOW | **`acceptInvitation` is check-then-act** (`workspaces.ts:318-340`). There is no transaction or conditional `WHERE accepted_at IS NULL`. Because the invite is bound to an email, the impact is limited to duplicate audit rows. | Use `UPDATE ... WHERE id=? AND accepted_at IS NULL RETURNING` as the claim, inside a transaction with the insert. | Two concurrent accepts produce exactly one `invitation.accepted` event. |
| SEC-12 | LOW (UNVERIFIED) | **`trustHost: true`** (`lib/auth.ts:109`). If `AUTH_URL` is not set in Vercel production, magic-link URLs are built from forwarded host headers. | Confirm `AUTH_URL` is set in the Vercel production env. | `vercel env ls production` lists `AUTH_URL`. |
