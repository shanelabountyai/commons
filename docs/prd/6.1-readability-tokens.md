# PRD 6.1 — Thread and board readability + native design tokens

**Status:** drafted 2026-11-02 for Shane's review (D-83: Phase 6 list approved as written). Governed by D-59 (Phase 6 = readability + uploads) and D-62 (tokens are native CSS custom properties, no dependency, landing with this work). Size L; delivered as two PRs on `phase-6` so each is reviewable alone. Builds only after PRs #5 and #6 merge and CI is green on `phase-5`.

## Problem

The forum reads as one ink at one weight, and the thread shows its structure only by indent. Reviewers found (design §1 #1/3/4/6/7/8/9/11/12 and §2; UX #7/8/12; a11y M1–M5 and §2):

1. **One ink, one weight.** Every border is `1px solid CanvasText` (`src/app/commons.css`): the error (`[role='alert']`), the scope note, a table cell and a code block are the same object; `.meta` and `.removed` differ from body text only by `opacity`. Nothing is red, nothing is muted by role, and the only type scale is the browser's default headings.
2. **The thread hierarchy is flat.** The post title is a default `h1`, every body and meta line is one size, and the only level cue is the `ol.thread ol` rail. A comment has no heading, so heading navigation in a 200-comment thread is one `h1` and one `h2`. A subtree cannot be collapsed; "M replies" is nowhere.
3. **The board list is unpaged and has no scan column.** `boardPosts` (`src/forum/view.ts:56`) returns every visible post (the fixture puts ~80 per board) and `[board]/page.tsx` renders them all; the meta order is `points · comments · by handle · YYYY-MM-DD` while Hot is entirely about age and `ago()` already exists (4.1.13).
4. **Nesting costs 2 rem a level** above 40 rem (1.25 margin + 0.75 padding; `commons.css`): depth 6 (the D-15 cut) is 192 px of a 360 px viewport. 4.1.13 dropped it to 1 rem under 40 rem; between 40 and 64 rem it is still 2 rem.
5. **Status markers are inconsistent.** Pinned and locked are CSS emoji (`.pin::before`, `.lock::before`), announced as "pushpin" or not at all; locked is text on the board but emoji on the thread `h1`; removed/deleted is `[removed]` italic at 0.8 opacity; "edited" is plain text; the queue (5.4 A) already uses a text `.badge`.
6. **Wayfinding.** Breadcrumbs are `<p class="meta">` with a dangling "›" on the board and thread pages; the permalink crumb has no board; "Settings: delete org" sits in the forum `<nav>` beside Boards; "permalink" and "Continue this thread →" repeat per comment with no distinguishing text (a11y M5); the permalink page flattens the tree into one `<ol>` with `marginLeft` (M1); a removed comment is announced as "Comment by removed" (M2).
7. **Scope note placement.** `<ScopeNote/>` renders on Boards, the board and the thread, where it sits between the post and the comments heading. The sentence must stay (CLAUDE.md), the placement need not.
8. **Empty states leak the CLI.** `f/page.tsx` tells a member to run `npm run commons:load`; the board says "Nothing here under this sort." for an empty board (sort does not filter); search shows "Posts (0)" with no sentence; the profile lists have none.

Already closed by 4.1.13 and not in scope: vote target size, `input size=`, line-height, table overflow wrapper, skip link, `<time dateTime>` in `ago()`/`when()`, page titles, the reduced-motion guard, user headings demoted (D-61).

## Part A — tokens, badges, board list, wayfinding, empty states (one PR)

- **Tokens** in `src/app/commons.css` `:root`, exactly the design review §2 block: a type scale `--fs-xs … --fs-xl` (1.2 ratio), a spacing scale `--sp-1 … --sp-8`, and five colour roles derived from system colours with `color-mix` so both schemes stay measurable: `--ink-muted` (meta, scope band), `--rule` (borders, the thread rail), `--accent` (`LinkText`), `--danger` (error, removed, banned), `--warn` (gated, warned, duplicate, locked), `--ok` (restored, cleared, notice), `--pin` (pinned row tint). `.meta` and `.removed` move from `opacity` to `--ink-muted`; `[role='alert']` to `--danger`, `[role='status']` to `--ok`; borders to `--rule`; `.body pre` and `blockquote` to `--rule`; the thread rail to `--rule`. No other visual change in this PR. Not on the ask-before-add list (PO D5).
- **`Badge`** in `src/components/forum.tsx`: `<span className="badge badge-<role>">` with text labels `Pinned`, `Locked`, `Removed`, `Deleted`, `Edited`, and the queue's existing kinds; `.pin::before` / `.lock::before` deleted. The board row and the thread `h1` use it; the queue's inline badge switches to it (same markup, one component).
- **Board list** (`[board]/page.tsx`, `boardPosts`): `boardPosts` keeps ranking every visible post (Hot sorts from the snapshot in memory) and returns a page: `take 25` after the pinned-first order, `?page=`, `pages` and `total` in the view. Row as a 2-column grid: the vote control and net points in a fixed `3.5rem` cell, then the title with its badges and one meta line `by <handle> · <ago> · N comments`. Relative age via the existing `ago()` (absolute in `title` and `dateTime`); the `YYYY-MM-DD` slice goes. The page size is a constant in the page, not in `rules/` (it is presentation, not a limit; D-15 is the depth cut and untouched). "New post" stays below the list with a jump link `#compose` in the breadcrumb row.
- **`Pager`** in `src/components/forum.tsx`: `<nav aria-label="…">` with Previous / Next and numbered links carrying `aria-label="Page N"` and `aria-current`. Used by the board page here; the thread's comment pager switches to it in Part B.
- **Breadcrumbs** on board, thread and permalink: `<nav aria-label="Breadcrumb"><ol>` with the board named on the permalink crumb and no dangling separator (the current page is the last item, text only).
- **Scope note once:** `ScopeNote` moves to a `<footer>` in `src/app/o/[org]/layout.tsx` as a muted band (`--ink-muted` on `--rule`), the sentence verbatim; the three page-level `<ScopeNote/>`s are deleted. "Settings: delete org" (owner only) leaves the forum `<nav>` for the same footer, so the forum nav is forum links only.
- **Empty states**, one sentence each, no commands: Boards — members see "No boards yet; ask an owner."; an owner sees "No boards yet." plus the existing create form if one exists (there is none today: say so, no form is added). Board — "No posts yet. Start one below." when the board has no visible posts; "Nothing in this window." only for a Top window that filters. Search — "No posts match." / "No comments match.". Profile — "No posts yet." / "No comments yet.".

## Part B — the thread (one PR)

- **Type hierarchy:** post `h1` at `--fs-xl`; the post body and comment bodies at `--fs-md`; meta at `--fs-sm`; the comments `h2` at `--fs-lg`. Spacing from the scale (`.post`, `li.c`, `.meta`).
- **Per-comment heading:** each `<article>` opens with `<h3 className="meta">` holding the author link (or the status word), so heading navigation lists every comment; the `aria-label` on the article is dropped in favour of the heading (one name, not two).
- **Removed placeholders named by status (M2):** the heading reads `Deleted comment` or `Removed comment (by moderator)` as visible text with the `Removed`/`Deleted` badge; no "Comment by removed".
- **Subtree collapse, no JS:** a comment's child `<ol>` is wrapped in `<details open>` whose `<summary>` reads `N replies shown` — N counted from the rendered rows below it on this page (the walk `Tree` already does), never from the tree module, and called "shown" because the page cut (D-15) and the comment page can hide descendants. Collapsing is a reader's browser state; the DOM keeps every comment, so axe, search and the XSS walk see the same page.
- **`Tree` shared (M1):** the nesting walk (flat rows with `depth` → nested `<ol>`) moves to `src/components/forum.tsx` taking a row renderer; the thread page passes `CommentView`, the permalink page passes its own row, and its `marginLeft` inline style goes. `src/tree/` is not touched: this is markup from rows the engine already rendered.
- **Indent:** `ol.thread ol { margin-left: clamp(0.5rem, 2vw, 1.25rem); padding-left: clamp(0.5rem, 1.5vw, 0.75rem) }` replacing the fixed values and the 40 rem media query. At 360 px depth 6 costs 6 × 1 rem = 96 px (was 192 px above the breakpoint, 96 px below it); at 1280 px it is 6 × 2 rem, as today.
- **Distinguishing link text (M5):** `permalink` gets `aria-label="Permalink to comment by <handle>"`; "Continue this thread →" becomes `Continue the thread under <handle>'s comment` with no arrow glyph. The e2e locator (`commons.spec.ts:65`) changes with it.
- **Comment pager** switches to the shared `Pager` (Previous / Next, `aria-label="Page N"`).
- **Thread meta line:** `by <handle> · <ago> · edited` (badge) · `permalink`; absolute time stays in `title`/`dateTime`. `ranked N ago` stays beside the sort tabs; the moderator-only hot score stays (4.1.5).

## Non-goals

- A CSS framework, a component library, client-side JS, a density toggle or identity tiles (PO §C).
- Any change to `src/tree/`, `src/render/`, a render rule (GR-), the page cut (D-15) or any expected file; `xss:check` must be byte-identical.
- Board descriptions (6.3), upload alt text and the upload panel (6.2), the ranking explainer page (design §1 #10; the constants are in `rules/ranking.json` and `docs/domain-brief.md`, a page is not needed for a learning project).
- Dropping or shortening the scope sentence.

## Acceptance

- **A:** e2e, each failing first — the board page shows 25 posts and a second page exists when the fixture board has more (`Page 2` link with `aria-current` after the click); a pinned post shows the text `Pinned` and the DOM holds no `📌`; the board meta line contains `ago` text with a `<time datetime>`; the scope sentence appears exactly once per page, in the `<footer>`, on Boards, board, thread, permalink, search, profile and queue; the forum `<nav>` holds no "delete org" link and the footer does for the owner; the empty-org Boards page contains no `npm run`. axe 0 at 320 / 768 / 1280, light and dark, on the board page and on Boards (the Phase 6 gate's three widths; `e2e/axe.ts` measures light and dark at whatever viewport the test set, so the three widths become a loop in the Phase 6 specs, not a harness change).
- **B:** e2e, each failing first — a thread's headings list includes one `h3` per rendered comment; a removed comment's heading reads `Removed comment (by moderator)` and a deleted one `Deleted comment`; `C-CHAIN` at depth 6 shows `Continue the thread under <handle>'s comment` and the permalink page renders nested `<ol>`s (an `ol ol` exists) with no inline `margin-left`; a comment with replies has a `<details open>` whose summary reads `N replies shown`; every `permalink` link has a distinct accessible name. axe 0 at the three widths, light and dark, on the thread, the permalink and the deep thread. `xss:check` 61/61 unchanged; `npm test`, harness 14/14, full Playwright green in CI.
- Both: `foundation:drift` clean (the org layout and `commons.css` are clone-owned; the members page is template-owned, which is why "delete org" goes to the footer and not there).

## Decisions this PRD asks of Shane (at review)

1. **Two PRs as proposed (A: tokens + board list + wayfinding; B: thread), or one.** Rec: two; A changes every page's colour and the footer, B the thread's markup, and each gets its own axe pass.
2. **Board page size 25** as a page constant, or in `rules/`. Rec: page constant; it is presentation, and `rules/` entries carry a golden case and a D- entry each.
3. **Subtree `<details>` open by default** (every comment in the DOM, collapse is the reader's act), or closed below depth 3. Rec: open; closed-by-default hides content from a first read and from the XSS walk's visible-text checks.
4. **"Delete org" to the footer** (owner only, beside the scope note), or dropped from the forum entirely (reachable from the template's settings pages). Rec: footer.
