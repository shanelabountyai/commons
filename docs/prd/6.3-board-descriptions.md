# PRD 6.3 — Board descriptions

**Status:** drafted 2026-11-03 (D-89); awaiting Shane's review. Governed by D-59 (Phase 6 scope), D-48 (the moderator is a Profile flag; `Role` is template-owned), non-negotiable 1 (user content is untrusted at every render) and rule 8 (fixtures frozen; this PRD asks for no regeneration). Size S, one PR. Builds on `phase-6.3` off `phase-6.2` (PRs #5–#9 still open).

## Problem

The Boards page is a bare list of slugs with post counts. Nothing says what belongs where. The UX review asks "which board for 'is this SBC good'?", and the design review notes that `off_topic` is a report reason while no board states its topic (`docs/reviews/2026-10-29-ux.md:42`, `-design.md:59`, PO consolidation §B5).

A re-read of the board path for this draft found one more gap:

1. **The board titles in the fixture are never used.** `fixtures/boards.csv` has titles ("Self-hosting", "Small-board computers"), but `loadForum` (`src/forum/load.ts:34`) creates every board with `title: slug`, and `loadFixtures` never reads `boards.csv`. So every org loaded by `commons:load`, `commons:demo` or the e2e setup shows `sbc`, `selfhosting` and so on as headings. It is not a defect in any rule; it is the same "nothing says what this board is" problem, one field over. Decision 2 asks whether to fix it here.

## Scope

- **Schema.** Migration: `Board.description String @default("")`. Empty means none. One line of plain text, at most 300 characters (the post title's limit).
- **Plain text, not markdown.** The description renders through `<Text>`, the same as a board title, so React encodes it. `src/render/` is not touched and `xss:check` stays 61/61, byte-identical. A link in a description shows as text, not a link.
- **The seed writes them.** `loadForum` gives each of the six fixture boards a description from a six-entry map in `src/forum/load.ts`, next to where the board is created. `fixtures/` does not change; the descriptions are seed copy, not fixture data. Draft copy, for review with the PRD:

  | slug | description |
  |---|---|
  | selfhosting | Running your own services: containers, reverse proxies, backups, the stack you'd rather not rent. |
  | networking | Routers, switches, VLANs, VPNs, DNS and anything else between the boxes. |
  | hardware | Servers, storage, power and cooling: what to buy, what broke, what it draws at idle. |
  | sbc | Raspberry Pi and other single-board computers: which board, which OS, which case. |
  | help | Stuck on something? Say what you tried, what you expected and what happened. |
  | meta | About this forum itself: boards, rules, moderation and bugs. |

  Orgs loaded before the migration keep `''` (`loadForum` is write-once and refuses `WRITE_ONCE` on a reload): the owner can add one, or the dev DB is reloaded. No backfill in the migration; copy does not belong in SQL.
- **Shown in two places.** On the Boards page, under each board's link and count (`<p className="meta">`). On the board page, as a `<p>` under the `h1`, which also puts it above the compose form, where the UX review asked for it. An empty description renders nothing, except to someone who can edit it (below), who sees "No description yet."
- **Editable by an owner or admin.** A new `describeBoard = orgAction('org.update', { boardId: ref('board'), description })` in `src/app/o/[org]/f/actions.ts`:
  - The template's `org.update` permission is owner and admin only, so no forum role is added. The invariant harness discovers the action by glob and covers it under INV-01..04/22 (permission, cross-org `ref`) with no registration; it goes 14 → 15.
  - The input is trimmed. `''` clears it. Otherwise it is refused `INPUT_INVALID` when it is longer than 300 characters or holds a C0/DEL control character (the alt check in `src/forum/uploads.ts:43`, which also refuses NUL and newlines). The check moves to one shared helper rather than a second copy.
  - The write records a template `audit` event, `forum.board.describe`, with `{ from, to }`. It does not go to the mod log: the mod log records actions on members and content, and a description has neither a subject nor a state (decision 3).
  - The form sits on the board page in a `<details><summary>Edit description</summary>` shown only when `can(ctx.role, 'org.update')`, through `ForumForm`, so a refusal renders the way every other forum refusal does.

## Non-goals

- A board create, rename or delete flow (the 6.3 row's "must not"). Titles stay as the loader writes them.
- Markdown or links in descriptions, board rules as a list, a report-reason hint that quotes the description (design review). The seam is the `description` field; a later PRD can render it through the sanitizer if links are wanted.
- Per-board moderators (declined for Phase 6). Any change to `fixtures/`, `src/render/`, `src/tree/`, a rules file or an expected file.

## Acceptance

- **Integration (`tests/integration/boards.test.ts`), red first:**
  - An owner sets a description; `boards()` returns it; one `AuditEvent` `forum.board.describe` with `from` and `to`.
  - An admin can; a member and a moderator-flagged member are refused (the harness covers the member; the moderator case is the one the harness cannot see, D-48).
  - 301 characters refused; a newline refused; a NUL refused; `'  '` clears to `''`.
  - `loadForum` on a fresh org writes all six descriptions; a second run inserts nothing (write-once unchanged).
- **Harness:** `inv-01-04-22-actions` 15/15 with `describeBoard` discovered.
- **e2e, failing first:**
  - The Boards page shows the `selfhosting` description under its link; the board page shows it under the `h1`.
  - A member sees no "Edit description"; the owner edits it and sees the new text on the board page and the Boards page.
  - A stored description of `<img src=x onerror=alert(1)>` renders as text: no `img` in the description's paragraph.
  - axe 0 on the Boards page and a board page at 320 / 768 / 1280, light and dark, with descriptions present.
- `fixtures:check` OK with `git diff --exit-code fixtures/` empty; `engine:eval` unchanged (15 files, 0 differences); `xss:check` 61/61; `engine:lint`, `foundation:drift`, `migrate diff` clean; vitest, full Playwright green in CI.

## Decisions this PRD asks of Shane (at review)

1. **Copy:** the six descriptions above, or your own wording. **Rec: as drafted**, edited freely at review; they are seed copy, not rules, and need no D- entry to change later.
2. **Board titles:** also make `loadForum` use `fixtures/boards.csv`'s titles ("Self-hosting" instead of `selfhosting`), reading the frozen file without changing it, or leave titles as slugs. **Rec: use the titles.** The fixture already says what each board is called, and a description under a slug heading still reads like a debug page. Cost: the e2e locators that click `selfhosting` / `networking` by name and the 4.1.13 page-title check (`/^selfhosting/`) change to the titles. Those are locators and a page title, not expected values (D-10 does not apply), and the URL slug is unchanged.
3. **Where the edit is recorded:** template `audit` only, or also a `ModerationAction` row in the public mod log. **Rec: audit only.** The mod log is for actions on a member or a node, and `ModerationAction` would need a nullable subject and a new kind for a configuration change.
4. **Who edits:** owner and admin (`org.update`), or moderators too. **Rec: owner and admin.** A moderator flag is for content and members (D-48); per-board moderators stay declined.

## Size

S, one session: migration and loader, the shared control-character check, the action and form, the two render sites, then the specs.
