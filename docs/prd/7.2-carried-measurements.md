## Problem

Four hypotheses have been carried since Phase 5 because the community fixture had no text (D-75, D-81, D-93 (3)). PRD 7.1 added the text (D-98). Each one can now be run through the bind test, which is unchanged from 6.4 and fixed before any number: a candidate **binds** when (a) today's rules allow the scripted attack, (b) the candidate refuses it, and (c) it refuses **0** community actions, with (c) non-vacuous.

**The line every number below carries:** *normal side = invented distribution (PRD 7.1 §1); a real community's rates are unknown.* A candidate that passes (c) passes against the generator's rates, which were fixed before this draft (D-97). That is the most this fixture can say.

## Scope

### 1. The `link` window (the one rule, if the oracle confirms it)

- **Rules.** One new window row in `rules/limits.json`: `{ "action": "link", "per_seconds": 86400, "max": 5, "young_max": 2 }` (decision 1). It is 2.5 × the community peak of 2 a day, and the young value sits on the young peak of 2, the same placement as 6.4's thread row. If the oracle finds a young community member above 2, the value is raised under this PRD's D- entry, never edited to pass (D-10).
- **Engine.** `linkHosts(body)` joins `src/limits/` (pure; the oracle's regex, `\]\(https?://([^/\s)]+)`, markdown links only). A body with k links needs k slots; `checkLimit` keeps its signature and the caller asks once per link, refusing the body at the first refusal. `engine:lint` validates the new action name.
- **Store.** The history is the links in the member's own `Post` and `Comment` bodies in the window. Body rows are truth, so there is no `LimitHit` column and no migration (decision 4, the 6.4 decision-4 precedent). `submitPost` and `submitComment` check it after the existing `guardAndRecord`, in the same transaction, and throw `RateLimited('link', retryAfter)`. The refusal text names the limit: "Five links a day for now; try again in …".
- **Oracle first.** `tools/limitslib.py` gains the link history; `tools/reference_rank.py --write-expected` adds two rows to `expected_limits.csv`:
  - `spam-link-rotation`: the attack above. Expected: 5 allowed, 15 refused, the first `retryAfter` from the first link.
  - `normal-community-links`: every community body with a link, replayed per author, 325 attempts. Expected: 0 refused.
- **The three copies.** The two rows go into `tools/reference_rank.py`, `scripts/abuse.ts` and `scripts/engine-eval-db.ts` in one commit, and `engine:eval:db` is run locally before the push (D-88).

### 2. Measured and recorded, no rule

`abuse:spam` / `abuse:normal` print, and `docs/EVAL.md` §Phase 7 — 7.2 records, one line each with the command and the invented-distribution line:

- **`min_contribution_chars`:** the downvotes refused at N = 2, 3, 10, 20 and 40, and the 1-char attack. No rule (decision 2). The aged-brigade signal (D-75) still flags the account that uses the trick.
- **Report swarm:** `engine:eval` runs the TypeScript detector (`src/limits/report-swarm.ts`) over `fixtures/community/reports.csv` and must agree with the oracle (0 signals); the line also records 2 young reports and the any-age peak of 4. This replaces D-81's "vacuous by construction" with a number.
- **Link hosts, the other two:** `young_links_per_body` 0 refuses 74; the same-host signal fires 206 times.
- **Repost:** signals raised on the 10 organic reposts at 86,400, 259,200 and 604,800 s, against the attack's 0 / 6. `duplicate.window_seconds` stays 86,400 (decision 3); its 2 community signals are the existing queue load, stated, not changed.

## Non-goals

- A rule for `min_contribution_chars`, repost or the host signal; any change to `report_swarm` or `duplicate`.
- Any classifier, host blocklist or allowlist, or reputation score (D-31). Pins (D-98 (4)).
- Changing a frozen fixture, an existing expected row or `fixtures/community/*`. Any change to `src/render/` or the ranking rules.
- A per-body link cap: the window already refuses a 6-link body, and the community never puts 2 in one.

## Decisions this PRD asks of Shane (at review)

1. **The link window: 5 per 24 h, young 2.** **Rec: as drafted.** It is the only candidate that passes all three tests, and it covers both host rotation and one-host repetition, because it counts links, not hosts. Alternative: record only, since the post window already slows the attack to 5 posts an hour.
2. **`min_contribution_chars`: record, no rule.** **Rec: record.** 40 refuses 6 community downvotes, and the only value that refuses none (2) stops a literal 1-char script but not "+1". Alternative: add it at 2 as a floor, stated as that.
3. **Repost: record; `duplicate.window_seconds` stays 86,400.** **Rec: record.** Any window that catches a 25 h repost also flags every organic one. Alternative: widen to 604,800 s as a signal only, which adds 10 community queue items for 6 attack ones.
4. **Where the link history comes from: the member's own body rows.** **Rec: body rows.** No migration, and the rows are already truth. Alternative: a link count on `LimitHit` and a migration.
