# Phase 1 — Pure engines + oracle agreement (no database writes)

Nothing is written to the database in this phase. Input is `fixtures/` loaded read-only in memory. Output is the `engine:eval` table and green goldens. No Prisma models beyond the template's, no UI. The exit bar: **the TypeScript tree and ranking engines agree with the Python oracle on every golden case and every fixture ordering, and the storage ADR is decided by a measurement.**

- [ ] **1.1 Scaffold.** Clone per KICKOFF.md (v1.4.0, port 7500). Scope banner verbatim in README. Model pin merged into `.claude/settings.json`. `?connection_limit=10&pool_timeout=20` on local `DATABASE_URL`s. `vercel.json` with the house `ignoreCommand`. CI `TZ=America/Chicago`. Billing and share links removed or unwired per D-18, recorded. Reuse scan skipped (cloud), recorded. Commands exist: `engine:eval` (prints `0 nodes` and exits 0 until 1.9), `engine:lint`, `fixtures:check`, `ranking:golden`. *Acceptance:* `foundation:drift` green; `npm test` green on the untouched template or recorded as CI-only with the reason.
- [ ] **1.2 Tree fixture generator + fixtures committed.** Write `tools/build_fixtures.py` (stdlib, seed 20261029, `T0 = 1793232000`): 6 boards, 200 users with account ages and contribution counts, 500 posts, 5,000 comments with a long-tail depth distribution, **one 1,000-comment thread** (`P-THICK`), **one 8-deep chain** with a mid-chain author delete and a mid-chain mod remove, a deleted leaf, a removed leaf, and vote rows (scripted patterns, including the GH/GW cases embedded as real posts). Write `tools/reference_rank.py --write-expected` → `fixtures/expected_post_order_{hot,top_day,top_week,top_all,new}.csv` and `expected_comment_order_best.csv` for named threads. Write `tools/verify_fixtures.py` (sha256 manifest). Add GR- tree goldens to `golden_answers.py` (depth, ancestors, render cut, D-13 leaf omission). Hashes into brief §5. **Commit fixtures before any test reads them.** *Acceptance:* two runs give identical bytes; `fixtures:check` OK on a clean checkout.
- [ ] **1.3 Port, with lineage.** Read Quorum's `tally-lint`, CSV reader and `fixtures:check` first; port; record donor paths in `docs/decisions.md` Lineage. *Acceptance:* `engine:lint` fails on a planted `Date.now()` in a throwaway branch and passes on the real tree.
- [ ] **1.4 Rules loader.** `src/rules/` zod schemas for `rules/ranking.json` and `rules/limits.json`; `RULES_INVALID` naming the field. *Acceptance:* both load; a negative gravity, a missing window and an unknown action are each refused by name.
- [ ] **1.5 Ranking engine.** `src/ranking/` `hot`, `wilson`, `inTopWindow`, `orderPosts(sort, now)`, `orderSiblings(sort, now)` with the D-9 tiebreak. *Acceptance:* GH-01..GH-07, GW-01..GW-08, GT-01..GT-03 in vitest with the oracle's tolerances; every `expected_*_order*.csv` matches row for row.
- [ ] **1.6 Tree engine + ADR-001 decided.** `src/tree/` path encode/decode, depth, ancestors, `buildThread(nodes, sort, page, now)` applying T-1..T-6 and D-13, `permalink(nodeId)`. Then measure: the `P-THICK` full-subtree fetch, median of 20, materialized path vs. closure table, **in a throwaway local Postgres if the sandbox has one, otherwise in memory with the method stated**. Fill the ADR decision record; close O-1 as a default and flag it for Shane. *Acceptance:* GR- goldens pass; the 8-deep chain renders `[deleted]`/`[removed]` in place with children intact; the deleted leaf is omitted but counted; page 2 of `P-THICK` starts at top-level comment 51; render cut at depth 6 produces continue-thread links.
- [ ] **1.7 Vote reducer.** `src/votes/` pure reducer over vote events: up / down / toggle-off / switch, self-vote per D-12 (author's +1 fixed), downvote gate per D-15 (needs account age + contributions as input; returns `GATED_DOWNVOTE`). *Acceptance:* every vote row in the fixture reduces to the fixture's expected counts; a self-downvote and a self-unvote are refused by code.
- [ ] **1.8 Rate-limit engine.** `src/limits/` pure sliding-window check `(history, action, account, now) → allow | {refuse, retryAfter}` from `rules/limits.json`. No storage yet. *Acceptance:* a scripted 60-comments-in-60-s burst from a young account allows exactly 2, then refuses with correct `retryAfter`; a normal-user script from the fixture never hits a limit.
- [ ] **1.9 `engine:eval`.** Prints: node counts, ranking agreement per sort (rows matched / total), golden counts, the ADR measurement, the limits scripts' allowed/refused counts. Exits non-zero naming the first disagreement. *Acceptance:* swapping two rows in a copy of an expected file exits 1 and names the row.
- [ ] **1.10 `docs/EVAL.md`.** Every number with the command that produced it, plus the scope banner's limits on what the numbers mean.
- [ ] **1.11 CI gate.** `fixtures:check`, `engine:lint`, `ranking:golden` (runs the Python oracle), `engine:eval`, vitest under `TZ=America/Chicago`. Prove the gate red on a throwaway branch (one expected row changed), then green. *Acceptance:* both runs linked in NEXT.md.

**Exit criteria:** all goldens green in both languages; every expected ordering matches; ADR-001 decided with a number; `engine:lint` OK; `docs/EVAL.md` exists; CI enforces the gate; PR open against `main`, not merged.

**Before Phase 2:** change `gravity_seconds` to 90000 in a copy of `rules/ranking.json`, re-run `engine:eval`, and confirm the hot orderings change and the diff names `expected_post_order_hot.csv`, with no code change. Then write `docs/phase-2-tasks.md` (schema for boards/posts/comments/votes/edit history via the tree module → one-vote unique constraint → denormalized counts + `votes:verify` → ranking batch job with `ranked_at` → `P-THICK` retrieval timing on the real schema) and stop for review.
