# Phase 4 — Moderation, pages, P1, and the capstone

Written at the Phase 3 gate (2026-10-29) for Shane's review. **Done 2026-10-29; see docs/CLOSEOUT.md.** Everything under the surface exists: pure engines, the schema, the writers, the action door, the renderer, the limits. Phase 4 is what people and moderators see. Exit bar: **reports flow into a queue with context; the content and user state machines are data with every transition logged append-only; the seeded community loads, renders, ranks and moderates end to end in a browser; the capstone demo runs from `docs/DEMO.md`; e2e and axe are green in CI.**

Read first: Handhold's community module (D-19) for the report/moderation vocabulary and its append-only audit test; Quorum D-22 for the state-machine-as-data shape; `docs/domain-brief.md` §3b for the refusal codes the UI must surface.

- [x] **4.1 Moderation schema.** `Report(reporterId, nodeKind, nodeId, reason ∈ closed set, createdAt)`, `ModerationAction(actorId, nodeKind/nodeId or profileId, kind, reason, createdAt)` append-only (trigger), `ReportReason` as rows (Handhold's pattern), the `moderator` role (clone-owned; owner/admin imply it). State machines as data: content `visible → reported → removed | cleared`, users `active → warned → banned(until) → active`; illegal transitions refused `TRANSITION_INVALID`. *Acceptance:* migration + `migrate diff` clean; trigger test; a transition table test.
- [x] **4.2 Report and act.** `submitReport` through the action door (the `report` window already exists), reporter count per node, author history; moderator actions remove / restore, lock thread, warn, ban (duration or permanent), unban; every action a `ModerationAction` row; ban enforcement already lives in the door (D-44). O-3's `SUSPECTED_BRIGADE` rows appear in the queue as items. *Acceptance:* the fixture's brigade shows as one queue item; remove→restore keeps both rows (Handhold's test, ported); a banned user's post is refused `BANNED_UNTIL` with the lift time.
- [x] **4.3 Pages.** Board list; board page with Hot/Top/New tabs and `rankedAt` freshness; thread page (Best/Top/New, pagination, continue-thread, permalink with ancestors); compose and reply forms through the action door with every refusal code shown as a message (`RATE_LIMITED` with its retryAfter); vote buttons; edit with the window mark; profile page (P1-2: history, counts); pinned posts per board (P1-1). All user text through `src/render` and nothing else (lint). *Acceptance:* Playwright walks the capstone; axe 0 violations light and dark; the XSS fixture bodies posted through the UI render inert in a real browser.
- [x] **4.4 Mod queue page.** Items with content in thread context, reporter count, author history, brigade signals; actions with reason required; the append-only log visible to admins. *Acceptance:* e2e: report → queue → remove → log row; restore → second log row.
- [x] **4.5 Duplicate-content defense (P1-3).** Hash of normalised body over a sliding window; a near-duplicate is accepted but queued with `SUSPECTED_DUPLICATE`. *Acceptance:* the spam-wave script posts the same body 20 times; 1 item in the queue per distinct body.
- [x] **4.6 Search (P1-4).** Plain full-text over title + body (Postgres `tsvector`); no semantic search (Footnote's lesson). *Acceptance:* a query returns the fixture post whose title contains it; removed content is excluded.
- [x] **4.7 Uploads (from Phase 3, D-40).** Type and size from `rules/limits.json`; stored outside the database; images shown through the renderer's allowlist only after this lands. *Acceptance:* 2 MB + 1 byte and an SVG refused by name; a PNG renders.
- [x] **4.8 Capstone.** `docs/DEMO.md`, three acts: (1) the same seed under Hot vs Top vs New side by side with `rankedAt`; (2) the spam-wave script live into the throttles and the queue; (3) a brigade on one post → one signal in the queue → moderator action → append-only log. Every number in it produced by a command named next to it.
- [x] **4.9 Closeout.** `docs/EVAL.md` §Phase 4; `WRITEUP.md` (the adversarial-design angle: every attack considered and the defense for each, with the fixture that proves it); brief artifact; LinkedIn posts; cost review; `docs/CLOSEOUT.md` by-hand list; build-log card to shipped. Deploy is a separate decision (not planned; synthetic data).
