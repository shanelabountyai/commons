# Commons UI design review (read-only; /home/claude/commons-app)

Scope read: prd-commons.md, docs/decisions.md, docs/DEMO.md, src/app/commons.css (the only stylesheet; imported by src/app/layout.tsx:2), layout.tsx, all seven `f/**/page.tsx`, src/components/forum.tsx, src/render/components.tsx, src/core/ui/action-form.tsx, rules/moderation.json, src/forum/view.ts:55-71.

## 1. Findings, ranked by impact on comprehension and trust

1. **One ink, one weight.** Every border is `1px solid CanvasText` (`nav`, `.scope`, `.body pre`, `th, td`, `[role='alert']` only differs by 2px). Error, scope note, table and code block are visually the same object; `.meta` and `.removed` differ only by `opacity`. Nothing is red, nothing is muted by role. Fix: 5 colour roles as CSS variables (below), derived from system colours with `color-mix`, so axe still measures real contrast.
2. **Vote control: two clicks, no state, tiny target.** ▲/▼ sit inside `<details>` (post/page.tsx:181-189, 77-84), so voting needs a disclosure click first; `.votes button { padding: 0 0.4rem }` gives roughly 20×22 px, under the 24 px WCAG 2.5.8 minimum; `view.ts` never loads the viewer's own vote, so a cast vote is indistinguishable from none, and the author's fixed +1 (D-12) reads as a live choice. Fix: move the two buttons out of `<details>` to the left of the meta line, min 32×32, `aria-pressed` from a `myVote` select, author sees a disabled "+1 (yours)".
3. **Thread hierarchy is flat.** Post title is a browser-default `h1`; body, comment bodies and all meta share one size; the only level cue is the `ol.thread ol` rail. `.meta` carries 6 facts separated by `·` (post/page.tsx:166-167) including `hot 14.65`, which D-9 says is "an implementation detail shown only in the eval". Fix: drop the raw score (keep "ranked N ago"), author+age first, points as a chip, actions as a row of text buttons.
4. **Board list: no primary scan column, no pagination.** `boardPosts` returns every visible post (view.ts:58, no `take`); the fixture puts ~80 posts per board on one page. Meta order is points · comments · author · `YYYY-MM-DD` ([board]/page.tsx:50) while the thread shows minute-precision UTC and nothing shows relative age, although Hot is entirely about age. Fix: 2-column row (points cell fixed 3.5rem | title + "by handle · 6 h ago · 12 comments"), page of 25 with `?page=`, relative age with `<time datetime>` title.
5. **Moderation queue cannot triage 50.** `queue.page_size` is 50 (moderation.json) and each item renders the full `<Markdown body>` (mod/page.tsx:63; bodies up to 50,000 chars) plus a form with a required reason field; no kind filter, no density, headings are 50 `h2`s. Fix: compact row (kind badge · title · author state · counts · opened), body in `<details>` with a 240-char excerpt, kind filter via `?kind=`, sticky "N open" bar. Also "Remove / Restore / Clear reports" are three submits in one form with no visual difference (post/page.tsx:150-151).
6. **Status markers are inconsistent.** Pinned = emoji via `.pin::before` (css:27), locked = text " · locked" on the board but emoji on the thread h1; removed/deleted = `[removed]` italic at 0.8 opacity; "edited" plain text; mod state in the queue is raw `c.status`/`modState` enum strings. Emoji render differently per OS and are announced ("pushpin"). Fix: one `<Badge kind>` component with text labels and role colours.
7. **Log table overflows.** Six columns incl. a 1000-char reason, `table` has no wrapper (css:25-26), so at 360 and 768 the page scrolls horizontally (body `max-width: 64rem; padding 0 1rem`). Target shows `POST 1a2b3c4d` (mod/page.tsx:114), not a link; `seq` (D-56) isn't shown. Fix: `.table-wrap { overflow-x:auto }`, link target, show seq, truncate reason with `title`.
8. **Responsive nesting.** Each level costs 2 rem (css:15: 1.25 margin + 0.75 padding); at depth 6 (D-15 cut) that is 192 px of a 360 px viewport, leaving ~136 px for text. `input size={60}` ([board]/page.tsx:60) is wider than 360 px. Fix: indent `clamp(0.5rem, 2vw, 1.25rem)`, collapse the rail below 480 px (depth shown as a count), inputs `width:100%`.
9. **Scope note placement.** `<ScopeNote/>` renders on boards, board and thread, and on the thread it sits between the post and the comments heading (post/page.tsx:226). Fix: once, in the layout footer, visually a muted band; keep the full sentence.
10. **rankedAt.** `ago()` (forum.tsx:16) only produces minutes, so a week-old snapshot reads "10080 min ago"; the note "(newest posts scored live)" is honest but unexplained. Fix: scale units and link the phrase to a one-paragraph "How ranking works" with the constants from `rules/ranking.json`.
11. **Empty states leak the CLI.** f/page.tsx:16 tells a member to run `npm run commons:load`; "Nothing here under this sort" is misleading (sort doesn't filter); search shows "Posts (0)" with no message; profile lists have none.
12. **Nav mixes trust levels.** "Delete org" sits in the forum nav beside Boards (layout.tsx:20). Move to Members/settings.
13. **Dark mode parity** is intact (system colours; `color-mix` on CanvasText), but `opacity: 0.85/0.8` on `.meta`/`.removed` lowers contrast equally in both and has no role meaning.

## 2. Minimal design system (data, native CSS, no library)

```css
:root{
 --fs-xs:.75rem;--fs-sm:.875rem;--fs-md:1rem;--fs-lg:1.25rem;--fs-xl:1.5rem;   /* 1.2 ratio */
 --sp-1:.25rem;--sp-2:.5rem;--sp-3:.75rem;--sp-4:1rem;--sp-6:1.5rem;--sp-8:2rem;
 --ink:CanvasText;--bg:Canvas;
 --ink-muted:color-mix(in srgb,CanvasText 65%,Canvas);
 --rule:color-mix(in srgb,CanvasText 20%,transparent);
 --accent:LinkText;                 /* links, active tab, upvote */
 --danger:color-mix(in srgb,red 70%,CanvasText);     /* error, removed, banned */
 --warn:color-mix(in srgb,orange 70%,CanvasText);    /* gated, warned, duplicate, locked */
 --ok:color-mix(in srgb,green 60%,CanvasText);       /* restored, cleared, notice */
 --pin:color-mix(in srgb,CanvasText 10%,Canvas);     /* pinned row tint */
 --target:2rem;
}
```
Native suffices: system colours keep contrast measurable in both schemes; no interactivity needs JS beyond server actions. Components, sized for Phase 5:
- `Badge` (pinned/locked/removed/deleted/edited/warned/banned/gated) — S
- `VoteControl` (pressed state, author lock, 32 px) — M
- `PostRow` (board list, 2-column) — M
- `MetaLine` (author · age · points · comments, `<time>`) — S
- `CommentCard` (header, body, action row, depth cue) — M
- `ActionBar` (text buttons replacing the verb-list `<summary>`) — S
- `Alert/Notice` (danger/ok/warn, used by ActionForm output) — S
- `QueueItem` (compact row + excerpt disclosure) — L
- `TableWrap` + `LogRow` — S
- `EmptyState` (title, one sentence, one action) — S
- `Pager` — S

## 3. Missed or should add
- **Board description/rules** (schema has slug+title only, commons.prisma:58-67): a one-line purpose under the h1 and a report-reason hint; rationale: "off_topic" exists as a reason but no board states its topic. M (migration + field).
- **Relative age with absolute title** everywhere; rationale: Hot's meaning is age. S.
- **User-selectable density** (compact/comfortable) via a cookie-set `data-density` on `<html>`; needed by moderators and power readers; S.
- **Identity cue**: deterministic initial-tile from the handle (no avatars, no uploads), plus "joined N d ago · N contributions" on hover; rationale: young-account gating is a core mechanic yet age is invisible in threads. M.
- **Onboarding for an empty org**: owner sees "Create your first board" form; members see "No boards yet, ask {owner}". S.
- **Limit feedback before refusal**: show "you can post N more this hour" near the form from the same engine; rationale: honest limits rule (PRD P0-4). M.
- **Ranking explainer** page linked from "ranked N ago". S.

## 4. Done well
1. Semantics: comments are real nested `<ol>` (post/page.tsx:38-57), tabs use `aria-current`, every form control is labelled, `role="search"`, and axe reports 0 violations light and dark on 10 page loads (D-55).
2. Honesty surfaces are already in the UI: `rankedAt` next to the tabs, "N top-level shown", upload limit in the label, `retryAfter` in the refusal text, GATED_DOWNVOTE notice.
3. One 28-line stylesheet of system colours delivers full light/dark parity with no theme code, and all user text reaches DOM through one `src/render` module.
